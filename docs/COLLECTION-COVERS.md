# 采集封面与影响力榜单

六个平台（抖音、小红书、今日头条、知乎、CSDN、B站）在当前详情元数据、视频poster或实际搜索卡片中读取封面。搜索卡片的封面跟随同一来源ID传入详情；知乎独立详情队列也保存该关联。不从相邻卡片、作者头像或任意正文插图推测封面。

封面独立字段为`coverUrl`、`coverUrls`、`coverSource`和`coverAssets`。正文图集仍用`images`／`imageUrls`，段落位置仍用`contentBlocks`。B站视频元数据的`pic`只进入封面字段；小红书图文首图兼作封面时保留图集中的原始位置，不从正文删除。不把单独封面追加到知识库图片识别队列。

每条详情读取完成后，在原页面关闭和视频转写之前，立即下载该记录已经观察到的封面并写入独立分组，随后连同正文一起入库；不额外打开原文、不等全任务结束再爬封面。各平台仍可并行，封面下载失败只记录缺口，不阻断正文或转写。Store的后台归档队列仅作为旧记录及其他写入入口的补偿，采集中已归档的封面不会重复下载。小红书优先使用当前笔记的cover或图集首图，不采用页面通用OG标志。文件放在配置的`outputDir/tasks/<任务ID>/covers/<平台>/<来源ID>/`，文件名按原URL哈希区分；不适合作为路径的ID用哈希代替。`coverAssets`保留原URL、完成／失败状态、本地相对路径、MIME、字节数、SHA256、保存或失败时间及错误原因。保存结果前回读最新内容，避免覆盖并发完成的正文与知识库数据。

启动时为既有明确封面补字段并排队归档。旧版B站第一张图片明确来自`pic`，可迁入封面分组；小红书图文首图标记为`first_gallery_image`。其他没有记录封面的旧文章不拿第一张正文图代替。下载失败不影响内容完成状态，保留原URL和失败原因；“补取／重试封面”串行重访当前任务已保存的原文链接，补取缺失或失效封面并归档。回填前同时核对页面与响应来源ID，不使用推荐图或任意正文图；保留并发更新的正文、转写和指标。小红书存在公开笔记或列表且普通登录弹窗有关闭按钮时正常点击关闭并重新检查访问状态；真正的登录限制、安全保护或验证码仍保留页面等待人工处理，同平台后续记录停止补取。知乎沿用配置中经过验证的独立未登录详情资料，不切换到通用登录资料。采集运行时禁止补取，补取中禁止启动采集，避免共用浏览器发生冲突。未提供显式封面的原文保留缺失状态。旧后端尚未重启时按钮仍显示“补存／重试封面”，只对已有地址归档并如实提示。

影响力榜单在标题旁显示固定尺寸缩略图，优先使用本地归档；未归档时尝试原图，缺图或加载失败显示占位，点击缩略图打开同一内容详情。详情分别展示封面原链接和正文图片资源；CSV、JSON导出携带独立封面字段。封面不参与影响力打分，排序规则保持不变。手机沿用现有卡片排版。
