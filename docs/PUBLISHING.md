# 图文发布

入口：文章创作 → 查看结果 → 发布文章。当前支持抖音文章和微信公众号文章；小红书、今日头条保留为后续渠道。

## 一键准备

选择渠道、插图版本、发布标题与封面方式。默认由 DeepSeek 阅读固定副本的全文，规划精简主题封面提示词，由豆包 Seedream 5.5 沿用已确认画风生成；也可选择正文插画。公众号还需填写作者（1–8字符），默认本机已确认的署名为“智媒锋传”。抖音标题最多30字符，公众号最多64字符。

“一键填好并保存草稿”固定正文和选定的插画版本，通过平台正常的 DOCX 导入入口上传。系统比对文字、插图数量与所在段落，填入标题、署名、封面、渠道支持的标签，然后保存草稿。公众号保存后重新加载草稿，核对标题、作者、封面、创作来源和全部图文；抖音通过“暂存离开→继续编辑”核对全文、标题、首页推荐头图及双列封面，再次“暂存离开”，最终停在草稿恢复入口。保存的编辑URL始终指向原草稿，不覆盖成离开后的入口URL。发布副本保留主标题，隐藏画布章节标题和引用编号，不修改创作原稿。

自动流程仅保存草稿，等待人工审核。界面的“打开平台人工审核”只打开浏览器，不调用发表动作；后端拒绝`publish:true`，避免误提交。已提交过的记录可以“另存为审核草稿”，保留原发布记录，复用全文、12张插画、标签和已生成封面，新草稿不会继承旧提交断点。

## 标签与封面

标签只来自同一采集任务的明确标签，由 DeepSeek 结合全文挑选至多5个，保存来源、选择理由与模型信息。抖音通过原生话题选择器精确选择；公众号不将推荐标签强加到正文中。

AI封面：公众号900×383（约2.35:1），抖音1080×1440（3:4）。公众号先用豆包支持的16:9生成，再完整缩放并补白，避免裁掉标题；抖音直接3:4生成。两渠道提示词、原图、下载断点、尺寸与哈希校验独立保存。封面不进入正文；不运行DeepSeek图片自动审核。上传使用平台原生封面选择器，并在发布弹窗提供预览和提示词。选择正文插画时保留原有封面流程。

抖音的“文章头图”和“封面设置”是两个独立位置，均使用固定副本中经过校验的主题封面文件，并选择“有文章头图”。不能只凭“编辑封面”按钮或历史coverReady标记判断成功：分别等待本次上传的新图片加载，记录各自的平台媒体路径，重开草稿后逐一比对；任一缺失、被替换或头图预览关闭，都不能记为准备完成。

公众号保存等待本次`operate_appmsg`成功回执后再重新加载核验，避免误用页面中旧的“已保存”提示。正文导入文档不重复放主标题（标题由独立字段填写），避免删标题后留下空段落。导入后清除空白段落，删除前后核对完整正文和图序；保留正常段落边界和图片。DOCX在末图后保留空段落；若平台导入只缺唯一末图，先逐块验证完整前缀，再经图片库入口补入末图，保存重开后仍须全部核对。

## 恢复与状态

发布记录、固定副本、已完成步骤及错误保存在本地 SQLite。选择历史记录后继续该记录，字段锁定，避免把旧任务与新设置混用；更改设置请“新建发布副本”。登录或验证码出现时暂停等待人工处理，处理后继续。页面里已有其他正文时，内容核验失败会停止，避免覆盖其他稿件。

`ready`表示完整草稿已保存；只有平台显示实际发表/发布成功才记录`published`，此状态不等同于审核通过或已公开可读。提交期间中断记为`submission_uncertain`，禁止自动重发。同一平台草稿的其他封面副本也不能绕过提交锁；草稿身份按平台ID确定，不受URL时间戳影响。

## 运行配置

`settings.local.json` 可配置 `publicationPython`（需 python-docx、Pillow）、`publishingCdpEndpoint` / `publishingProfileDir`（抖音）、`wechatPublishingCdpEndpoint` / `wechatPublishingProfileDir`（公众号）。也可由适配器启动独立浏览器资料。浏览器登录资料、模型凭据和发布文件不进入 Git。中间 DOCX、封面及固定副本放在配置的 `outputDir/publications/`。

首次连接公众号和抖音发布专用浏览器时，按平台流程手动登录。平台 UI 更新可能使选择器失效，任务会停在可恢复状态并显示错误，不声称发布成功。
