# 知识库文本与图片预处理

采集原始正文 `body`、转写 `transcript`、原始图片链接保持可核对。知识库另存 `knowledge`，创作语义拆分、本地向量化和召回统一读取 `knowledge.text`。旧创作及已生成文章保存原快照，不自动覆盖。

## 文本与图文顺序

- 清除普通正文的 Unicode 表情、已知平台表情标记、零宽字符和多余空白行；保留段落换行、数学符号、引用编号及代码块内缩进与空行。
- 通过正常页面 DOM 访问正文，按顺序保存 `contentBlocks`。正文中图片使用 `inline_dom`；独立轮播图记为正文前／后图集，保留实际 DOM 顺序。代码、图片说明和相邻文字均作为顺序块保存。
- 过滤明显头像、表情与工具栏资源；同一 CDN 图片的常见变体去重。模型进一步识别纯装饰图片，不把其当作文章信息。
- 历史采集只有图片列表时，原始段落位置无法还原。标记 `unknown_legacy`，描述以明确标注位置未知的附录形式保存，不伪造段落锚点。只有正常重访原文重新提取，才能补回准确位置。

## 图片信息补充

使用已配置的 DeepSeek Flash 和原有加密密钥。发送真实图片字节，并附带标题、相邻段落和图片说明作为消歧上下文；不发送浏览器登录资料。支持 PNG/JPEG/WebP/GIF，单图最大10MB；失效或访问受限资源保留缺口，不绕过限制。

模型返回自然语言描述、清晰可辨文字、识别限制，并区分 `content / decorative / unreadable`。成功描述放回对应图文块，显式标记为模型识别内容。模糊文字和数字不得猜测。知识文本的分块保存重叠图片的 `imageSources`，可追溯原图、模型及原始位置。

图片按内容哈希、模型和识别规则版本缓存，串行请求以限制内存与并发。每张图处理后保存断点；失败不冒充成功。可在内容库“知识库预处理”查看进度、暂停、重试失败图片。新采集自动入队；历史记录先进行文本清洗，点击按钮处理已有图片。

## 创作衔接

新创作在拆解框架前完成其来源快照的图片预处理，再重新计算段落、分块与内容哈希。已有缓存复用；失败图片只记缺口，不编造描述。源文章采集信息若在处理中更新，旧快照的结果不会覆盖新记录。参考文章仍独立于其他文章召回库。

已有创作保留原证据快照；需要使用新补充图片时，创建新创作。导出 JSON 和 CSV 均保留原始字段、顺序块和知识库处理结果。
